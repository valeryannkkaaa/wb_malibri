# Модуль управления рекламой WB — руководство пользователя

Документ для заказчика. Описывает: что показывает система, где что смотреть и как считается
каждая цифра на экране.

Стенд: **https://wb.zhukovlab.ru/advert** (тестовая среда, вход через общий портал).
Дата описания: 24.07.2026. Пилот: 10 товаров, 10 рекламных кампаний типа «Поиск».

---

## 1. Что делает система

Каждые несколько часов система:

1. забирает из API Wildberries статистику рекламных кампаний по каждому ключевому слову
   (показы, клики, заказы, цена клика, текущая ставка);
2. забирает аналитику товара: воронку продаж по дням и отчёт «Поисковые запросы по товарам»;
3. сама ходит в поиск Wildberries и смотрит, на какой позиции стоит товар по главному ключу
   (в трёх городах: Краснодар, Москва, Ростов) и кто стоит рядом в выдаче;
4. считает для каждого ключа **предельно допустимую цену клика** по юнит-экономике товара;
5. сравнивает факт с этим пределом и выдаёт **рекомендацию**: снизить ставку, поднять, исключить
   ключ, оставить как есть.

> **Важно.** Сейчас система работает в режиме `suggest-only` — она **только советует**.
> Ставки в рекламном кабинете WB не меняются автоматически. Все решения из журнала менеджер
> применяет руками. Это осознанное ограничение на время пилота.

## 3. Дашборд `/advert`

### 3.1 Строка статуса (серые плашки сверху)

| Плашка | Что означает |
|---|---|
| **Цикл: ок / устарело / выполняется / ошибка** | Здоровье фонового цикла. «Устарело» — последний цикл завершился больше 30 минут назад; «ошибка» — цикл упал с ненулевым кодом |
| **Синхронизация: дата** | Когда последний раз забирали статистику рекламы из API WB |
| **Парсер: Краснодар / Москва / Ростов** | Выпадающий список — регион, из которого система смотрит поиск WB. Позиции в разных городах отличаются, потому что WB выдаёт товары ближайших складов. Рядом в скобках — технический код региона (`dest`) |
| **Краснодар 3/10 · Москва 3/10 · Ростов 3/10** | По скольким товарам из 10 удалось найти позицию в каждом городе |
| **Позиции (rostov): 3/10** | То же по текущему выбранному региону |
| **Остатки: дата** | Когда последний раз обновляли складские остатки |
| **Срезы: дата · N циклов** | Когда система записала последний «слепок» состояния (для графиков истории), сколько циклов прошло за сегодня |
| **Алерты: N (M крит.)** | Сколько проблем найдено; в скобках — сколько из них критические |

### 3.2 Плитки-счётчики

- **SKU** — сколько товаров в пилоте.
- **Ключей** — сумма ключевых слов по всем кампаниям.
- **Заказы 7д** — сумма заказов с рекламы за последние 7 дней по всем кампаниям.
- **Юнит-экономика 10/10** — по скольким товарам известна цена (из API или из ручного файла).
  Без цены нельзя посчитать предел цены клика.
- **Ключи в базе 10/10** — по скольким кампаниям выгружены полные списки ключей.
- **Рекомендаций** — сколько советов показано в блоке ниже (максимум 5).
- **Алерты** — сколько проблем.

### 3.3 Таблица «Алерты»

Три типа проблем, отсортированы: сначала критические, потом предупреждения.

| Тип | Когда возникает | Критичность |
|---|---|---|
| **Нет остатка** | Складской остаток товара = 0, а реклама крутится — деньги уходят впустую | критично |
| **Парсер 429** | Wildberries временно заблокировал наши запросы к поиску (лимит частоты), позиция не обновилась. Отдельный алерт появляется, если таких отказов ≥ 3 за 6 часов | критично |
| **CPC выше лимита** | Фактическая цена клика по главному ключу выше расчётного предела — реклама по этому ключу не окупается | предупреждение |

### 3.4 Таблица «Рекомендации»

Топ-5 свежих советов: сначала те, где надо что-то делать (снизить, поднять, исключить, перевести
в managed), потом «оставить». Из истории берутся самые новые советы, дубли по паре
«кампания + ключ + действие» отбрасываются.

### 3.5 Таблица «Кампании» — по одной строке на товар

| Столбец | Что в нём |
|---|---|
| **Кампания** | Номер рекламной кампании в WB (ссылка на карточку) |
| **Артикул** | Номенклатура WB (`nm_id`) |
| **Главный ключ** | Основной поисковый запрос товара — по нему меряются позиция и CTR. Задан вручную в настройках либо выбран автоматически как ключ с максимумом заказов |
| **Цель** | Целевая позиция в выдаче: топ 1–3 / поз. 4–10 / поз. 10–20 |
| **Заказы** | Заказы с рекламы за 7 дней |
| **CTR, %** | Кликабельность за 7 дней |
| **CPC, ₽** | Фактическая средняя цена клика по главному ключу. Красным — если выше предела |
| **Макс. CPC** | Расчётный предел цены клика (см. раздел 5.4). Значок `~` рядом означает: собственных данных по ключу мало, предел оценён по среднему — доверять с осторожностью |
| **Позиция** | Место в поиске WB по главному ключу в выбранном городе. `✓` — цель достигнута, `✗` — хуже цели, `—` — товара нет в первых 500 местах или парсинг не удался |
| **Рекомендация** | Главный совет по этой кампании + сколько ещё действий в очереди |
| **Остаток** | Складской остаток, в скобках — сколько единиц в пути |

Строки с проблемами подсвечиваются: красноватым — критические алерты, желтоватым — есть
невыполненные действия.

## 4. Карточка кампании `/advert/products/<номер>`

Пример: `/advert/products/33206165` — «перчатки для уборки».

**Шапка** — плитки: главный ключ, показы за 7 дней, заказы за 7 дней, CTR, фактический CPC
главного ключа, предел CPC, позиция, остаток.

**Строка «Цена для лимита»** — самое важное для понимания расчётов:

> Цена для лимита: 180.46 ₽ (воронка WB) · выкуп 95.2% · CSV 176 ₽ · маржа 11% · DRR макс. 15.0%

Здесь видно, какая цена подставлена в формулу предела, откуда она взята, какой процент выкупа
и какой максимальный ДРР (доля рекламных расходов) заложен.

**Графики** — позиция в выдаче (чем ниже линия, тем лучше) и CTR главного ключа во времени.

**История парсинга** — последние 10 замеров позиции с точным временем.

**Соседи по выдаче** — топ-10 товаров, которые стоят рядом в поиске по главному ключу: бренд,
цена, рейтинг, число отзывов. Над таблицей — сравнение нашей цены с медианой соседей либо
предупреждение «Нас нет в текущем срезе выдачи» (значит товар ниже 10-го места).

**Поисковые запросы** — отчёт WB по запросам, приведшим на карточку: частота в неделю, медианная
позиция, видимость, заказы, конверсия «корзина → заказ» и перцентиль (позиция товара среди
конкурентов по этому запросу; зелёный ≥ 70, красный ≤ 30).

**Динамика продаж** — воронка по дням: сводки за 7 и 30 дней (заказы, выручка, средний чек,
конверсии, выкуп) и подневная таблица за последние 14 дней.

**Рекомендации и предупреждения** — советы по всем ключам этой кампании + технические пометки
вида «33 из 36 ключей: потолок оценён по приору» или «у 30 из 36 ключей нет ставки в данных WB».

**Ключевые слова** — полная таблица ключей: показы, клики, CTR, CPC, заказы, статус.
Главный ключ помечен звёздочкой ★.

Статусы ключа:
- **Ждём 100 показов** — ключ ещё не набрал 100 показов, решения по нему не принимаются;
- **Управляется** — ключ в работе, правила к нему применяются;
- **Исключён** — ключ помечен на отключение.

## 5. Все расчёты

### 5.1 Базовые метрики рекламы (период — 7 дней)

- **CTR, %** = клики ÷ показы × 100. Если WB присылает готовый CTR — берётся он.
- **CPC, ₽** (фактическая цена клика) = расход ÷ клики. Расход считается как
  «цена клика из API × число кликов».
- **Заказы, показы, клики** — как есть из отчёта WB `normquery/stats` за окно
  «сегодня минус 7 дней».
- **Статус ключа**: 100 показов и более → «управляется», меньше → «ждём 100 показов».

> **CPC ≠ ставка.** Ставка — максимум, который вы готовы платить; CPC — сколько фактически
> списалось в среднем. Поэтому в журнале нормальна запись вида «CPC 6.04 ₽ → ставка 7.2 ₽»:
> снижается именно ставка, а CPC приведён для контекста.

### 5.2 Цена товара для расчётов

Берётся первый доступный источник по приоритету:

1. **Воронка WB** — средний чек за всю доступную историю продаж:
   сумма заказов в рублях ÷ количество заказов. Это цена, по которой реально покупают,
   с учётом скидок и СПП, — она может отличаться от цены на витрине.
2. **Поисковый отчёт WB** — минимальная цена из отчёта.
3. **Ручной файл `unit_economics.csv`** — цена, введённая менеджером.

Источник всегда подписан на карточке товара. Переход на данные API убрал старую проблему
занижения цены: по одному товару в ручном файле стояло 179 ₽ при фактических 471 ₽.

### 5.3 Процент выкупа

Средневзвешенный по количеству заказов процент выкупа из воронки:

```
выкуп % = Σ (выкуп_за_день % × заказы_за_день) ÷ Σ заказы_за_день
```

Если WB не прислал процент по дням — считается как
`сумма выкупов в рублях ÷ сумма заказов в рублях × 100`.

### 5.4 Конверсия клика в заказ (CR) — со сглаживанием

Прямое деление «заказы ÷ клики» на малых числах врёт: один заказ на трёх кликах даёт 33%.
Поэтому используется сглаживание к среднему (байесовское, стандартная практика в контекстной
рекламе). Расчёт двухуровневый:

```
CR_кампании = (заказы_кампании + 50 × CR_общий) ÷ (клики_кампании + 50)
CR_ключа    = (заказы_ключа    + 50 × CR_кампании) ÷ (клики_ключа    + 50)
CR_итог     = min(CR_ключа, 2 × CR_кампании)
```

- **CR_общий** — конверсия по всему пилоту: все заказы ÷ все клики.
- **50** — «сила приора»: пока у ключа мало кликов, оценка тянется к среднему по кампании;
  чем больше данных, тем ближе к собственной цифре ключа.
- **Ограничение сверху вдвое от кампании** отсекает выбросы: WB иногда атрибутирует ключу
  больше заказов, чем было кликов.
- Если у ключа **меньше 30 кликов**, рядом с пределом ставится значок `~` — «оценка по среднему».

### 5.5 Предел цены клика («Макс. CPC») — ключевая формула

```
Макс. CPC = цена товара × выкуп % × максимальный ДРР % × CR
```

Смысл: сколько можно платить за клик, чтобы реклама уложилась в заданную долю расходов.
Если из 100 кликов заказ делают 20 (CR = 0.2) и с каждой покупки допустимо потратить
на рекламу 15% от 180 ₽ выкупленного товара, то на один клик приходится
`180 × 0.952 × 0.15 × 0.196 ≈ 5.04 ₽`.

- **Максимальный ДРР** берётся из настроек товара, по умолчанию 15%.
- Выкуп учитывается, потому что заказ ≠ деньги: часть заказов возвращают.
- Если нет цены — предел не считается, в интерфейсе появится предупреждение.

Это стандартная модель target-ACOS: сколько платить за клик = выручка с клика × допустимая доля.

### 5.6 Правила рекомендаций

Проверяются по порядку сверху вниз; срабатывает первое подходящее.

| № | Условие | Решение |
|---|---|---|
| 1 | Ключ в статусе «ждём 100 показов», но показов уже ≥ 100 | **В managed** — перевести в работу |
| 2 | Ключ всё ещё «ждёт 100 показов» | решение не принимается |
| 3 | Показов ≥ 300, кликов 0 | **Исключить ключ** — запрос нерелевантен |
| 4 | Главный ключ: показов ≥ 200, заказов 0, CTR < 2% | **Исключить ключ** — карточка не откликается на свой же запрос |
| 5 | Второстепенный ключ: показов ≥ 100, заказов 0, CTR < 1% | **Исключить ключ** (с пометкой «перетестировать через 30 дней») |
| 6 | Кликов ≥ 5 и фактический CPC **выше** предела | **Снизить ставку** |
| 7 | Главный ключ, кликов ≥ 5, CPC **ниже 80%** предела, заказов ≥ 5, предел посчитан на своих данных (не по среднему) | **Поднять ставку** |
| 8 | Главный ключ работает, но запаса для роста нет | **Оставить** |
| 9 | Ничего из перечисленного | пропустить — данных мало либо всё в норме |

Три ценовые зоны в правилах 6–8: **выше предела** — снижаем; **80–100% предела** (буферная
зона) — не трогаем; **ниже 80%** — есть запас, можно расти. Буфер в 20% нужен, чтобы не
дёргать ставку туда-обратно на шуме.

**На сколько меняется ставка:**

- снижение — на 10%, но не более чем на 5 ₽ за раз;
- повышение — на 5%, жёсткий потолок 1500 ₽;
- рост запрещён, если предел посчитан по среднему (значок `~`) — сначала нужны свои данные.

Исключение ключа приоритетнее ценовых правил: нерелевантный запрос сначала отключают,
а не торгуются за его ставку.

### 5.7 Позиция в поиске

Система запрашивает поиск Wildberries по главному ключу, до 5 страниц по 100 товаров,
и ищет наш артикул:

```
позиция = (номер страницы − 1) × 100 + место на странице
```

Если товара нет в первых 500 — записывается «не в топ-500». Замер делается по каждому
из трёх городов отдельно: выдача WB зависит от ближайших складов. Технический код города
(`dest`) система запрашивает у геосервиса WB на каждом цикле, чтобы он не устаревал.

**Цель достигнута (`✓` / `✗`)** — сравнение позиции с целевым грейдом: топ 1–3 → позиция ≤ 3,
поз. 4–10 → ≤ 10, поз. 10–20 → ≤ 20.

### 5.8 Соседи по выдаче

Из уже загруженной первой страницы поиска берутся первые 10 товаров (дополнительных запросов
к WB не делается). Считается **медиана цен соседей** (наш товар из расчёта исключён) и разница
с нашей ценой: «дороже медианы на X ₽» / «дешевле на X ₽».

### 5.9 Сводки воронки за 7 и 30 дней

- **Заказы, выручка** — суммы за период.
- **Средний чек** = выручка ÷ заказы.
- **Конверсии «в корзину», «в заказ», «выкуп»** — средневзвешенные по числу заказов за день
  (день с 80 заказами влияет на среднее сильнее, чем день с 5).
- Если истории меньше, чем период, рядом подписано фактическое число дней.

### 5.10 Сводка рекомендации в строке кампании

По кампании может быть много советов, в таблицу выносится один. Приоритет действий:
исключить ключ → снизить ставку → поднять ставку → в managed → оставить → пропустить.
При равенстве побеждает совет по главному ключу. Остальные показываются как «ещё N действий».

## 6. Откуда берутся данные и как часто обновляются

Полный цикл запускается на сервере **каждые 4 часа** и состоит из 7 шагов:

| Шаг | Что делает | Охват за один запуск |
|---|---|---|
| 1 | Статистика рекламы (`normquery/stats`, `get-bids`, `fullstats`) | 3 кампании по очереди |
| 2 | Отчёт «Поисковые запросы по товарам» | 1 товар по очереди |
| 3 | Воронка продаж по дням (`nm-report`) | 1 товар по очереди, первая выгрузка — за 365 дней, дальше только новые дни |
| 4 | Расчёт рекомендаций | все товары |
| 5 | Позиции в поиске + срез конкурентов | все товары × 3 города |
| 6 | Складские остатки | все товары, не чаще раза в сутки |
| 7 | Запись «слепка» для графиков и истории | все товары |

Ротация (шаги 1–3) нужна из-за лимитов WB на частоту запросов: система обходит товары по
кругу, первым берётся тот, к кому дольше всего не обращались. Поэтому свежие данные по
воронке и поисковому отчёту появляются не у всех товаров сразу — блок в карточке честно
пишет «данные подтягиваются по ротации».

> Подпись «авто-цикл каждые 15 мин» в шапке дашборда — из конфигурации пилота; фактическое
> расписание на сервере сейчас **раз в 4 часа**. Расхождение косметическое, на расчёты не влияет.

Источники:

| Данные | Источник |
|---|---|
| Показы, клики, заказы, CPC, ставки | API WB, рекламный кабинет |
| Цена, выкуп, конверсии, выручка | API WB, аналитика (воронка `nm-report`) |
| Частота запросов, медианная позиция, перцентили | API WB, отчёт «Поисковые запросы по товарам» |
| Остатки | API WB, склады |
| Позиция в выдаче, цены и рейтинги соседей | Публичный поиск Wildberries |
| Целевая позиция, максимальный ДРР, маржа | Файл настроек, заполняет менеджер |

## 7. Ограничения текущей версии — честно

1. **Ставки не пишутся в WB.** Режим `suggest-only`, запись отключена и на уровне настроек,
   и на уровне токена. Все рекомендации применяются вручную.
2. **По большинству ключей предел оценён по среднему** (значок `~`). За 7-дневное рекламное окно
   ключ редко набирает 30 кликов. По таким ключам система не разрешает повышать ставку.
   Данных воронки за 365 дней теперь достаточно, чтобы уточнить эти оценки, — это следующий шаг.
3. **По части ключей WB не отдаёт текущую ставку** — по ним рекомендации по ставке не строятся,
   об этом пишется прямо в карточке.
4. **Поисковый отчёт и воронка догружаются по одному товару за цикл** — полный охват набирается
   за несколько суток.
5. **Парсер позиций упирается в лимиты WB** (ошибка 429). Замер по такому товару пропускается
   до следующего цикла.
6. **Два источника позиций пока не сведены**: собственный парсер выдачи и медианная позиция из
   отчёта WB могут расходиться — они меряют разное (мгновенный срез против недельной медианы).
7. **Покрыт один тип рекламных кампаний** — с ручной ставкой в поиске. Кампании за клик,
   расписания день/ночь, автопополнение бюджета и полки конкурентов в пилот не входят.

## 8. Глоссарий

| Термин | Значение |
|---|---|
| **SKU / артикул / nm_id** | Номенклатура товара в Wildberries |
| **Кампания** | Рекламная кампания WB (тип «Поиск») |
| **Главный ключ (primary)** | Основной поисковый запрос товара |
| **CTR** | Доля показов, закончившихся кликом |
| **CPC** | Фактическая средняя цена клика |
| **Ставка** | Максимум, который вы готовы заплатить за клик |
| **CR** | Конверсия клика в заказ |
| **ДРР** | Доля рекламных расходов в выручке |
| **Приор** | Среднее значение, к которому подтягивается оценка при нехватке данных |
| **Перцентиль** | Место товара среди конкурентов по запросу: 90 — лучше 90% конкурентов |
| **Ротация** | Обход товаров по кругу из-за лимитов API |
| **suggest-only** | Режим «только советы», без записи в рекламный кабинет |
